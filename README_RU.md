# CV Container Ship v1.11 — сборка Windows EXE через GitHub

Эта сборка предназначена для Windows. Python не требуется устанавливать на компьютере, где будет запускаться готовый `CV_Container_Ship_v1.07.exe`. GitHub Actions использует временную Windows-среду, чтобы собрать приложение и подготовить файл для скачивания.

## Новое в v1.07

- Импорт координат скелета из листа `POSITIONS` шаблона Vessel Skeleton.
- Кнопка переключения пустого скелета и плана с контейнерами; записи EDI при этом не удаляются.
- Цветовое выделение внесённых/ограниченных позиций и толстая линия границы палубы и трюма в поперечной схеме Bay.
- Экспорт JPG пустого скелета. Строки DEMO не используются как реальные координаты.

- Переключение графики между `Full Plan` и кратким `Stowage Plan`.
- В кратком плане верхняя строка показывает POD или короткое обозначение типа контейнера; нижняя строка — вес в целых тоннах с округлением (24 600 кг → 25).
- Новая вкладка `Справочник (Data)` с разделами портов, типов ISO и других значений. Справочники можно редактировать; они сохраняются локально в настройках приложения.
- Встроены стартовые отображаемые обозначения ISO, включая согласованные HR, FR, OS и FS.

## Новое в v1.05

- Комплексная проверка плана перед экспортом EDI: дубликаты, поля, ISO, координаты, масса, конфликты позиций 20/40/45 ft и доступные позиции из выбранного скелета.
- Список замечаний с переходом к контейнеру и выделением на схеме.
- Быстрый поиск по номеру контейнера, POD/POT/POL, линии, типу ISO, Bay, Row, Tier и Booking.
- Сравнение исходного плана с текущими данными: добавленные, удалённые, перемещённые и изменённые записи.
- Перемещение контейнера через графику: выбрать контейнер, затем пустую целевую позицию. Программа проверяет пересечения слотов.
- Экспорт графики в JPG для текущего режима Tier или Bay с выбранной цветовой раскраской и легендой.

Существующие функции v1.04 сохранены: импорт EDI/Excel, редактор, планы Tier/Bay, статистика, проекты, автосохранение и резервные копии, экспорт EDI и Excel в режимах Tier/Bay/Complex, образец и пустой шаблон Excel.

Проверка размещения — это структурная проверка данных, а не расчёт остойчивости судна и не сертификация EDI для любого терминала.

## Состав архива

- `app.py` — приложение.
- `app.ico` — иконка.
- `requirements.txt` — зависимости, устанавливаемые только на машине сборки.
- `EDI_Input_Template.xlsx` — встроенный образец Excel.
- `Vessel_Skeleton_Template.xlsx` — шаблон координат и ограничений судна для листа POSITIONS и справочных данных.
- `.github/workflows/build-windows.yml` — GitHub Actions workflow.
- `WORKFLOW_TO_COPY.yml` — тот же workflow в отдельном файле для удобного копирования через браузер GitHub.
- `CHANGELOG_V1.07.md` — список изменений.

## Вариант A — использовать существующий репозиторий GitHub

1. Скачайте архив `CV_Container_Ship_v1.07_GitHub_Build.zip` и извлеките его.
2. Откройте свой репозиторий GitHub, используемый для v1.03/v1.04.
3. Через `Add file` → `Upload files` загрузите из извлечённой папки в корень репозитория файлы `app.py`, `app.ico`, `requirements.txt`, `EDI_Input_Template.xlsx`, `Vessel_Skeleton_Template.xlsx`, `README_RU.md` и `CHANGELOG_V1.07.md`. Подтвердите через `Commit changes`.
4. Обновите workflow: на странице репозитория откройте `.github/workflows/build-windows.yml`, нажмите кнопку редактирования (карандаш), замените всё содержимое текстом из `WORKFLOW_TO_COPY.yml` и сохраните через `Commit changes`.
   - Если файла `.github/workflows/build-windows.yml` пока нет, выберите `Add file` → `Create new file` и в поле имени напишите `.github/workflows/build-windows.yml`, затем вставьте код из `WORKFLOW_TO_COPY.yml`.
   - Если папка `.github` не загружается через браузер, не загружайте её отдельно: создайте или отредактируйте этот файл прямо на сайте GitHub.
5. Откройте `Actions` → `Build CV Container Ship v1.07 for Windows` → `Run workflow`. Если workflow запускается автоматически после commit, вручную повторно запускать его не нужно.
6. Дождитесь завершения workflow. Зелёная галочка означает, что сборка успешно завершилась.
7. Откройте страницу запуска и найдите раздел `Artifacts`. Скачайте `CV_Container_Ship_v1.07_Windows_EXE`.
8. Распакуйте загруженный ZIP. Внутри должен быть `CV_Container_Ship_v1.07.exe`.

## Вариант B — новый репозиторий

1. Создайте приватный репозиторий на https://github.com/new.
2. Загрузите файлы проекта в корень репозитория.
3. Создайте или обновите `.github/workflows/build-windows.yml` текстом из `WORKFLOW_TO_COPY.yml`.
4. Откройте `Actions` и запустите `Build CV Container Ship v1.07 for Windows`.
5. Скачайте готовый `.exe` из `Artifacts`.

## Рабочие папки приложения

Проекты остаются отдельно от EXE, в `Документы\CV Container Ship\Projects`. Экспорт, резервные копии и данные восстановления хранятся в отдельных подпапках этой же рабочей папки. Обновление приложения не должно удалять их.

## Важно

- В архиве находится исходный проект и workflow для сборки, но не сам `.exe`.
- Для сборки требуется доступный GitHub Actions и успешный запуск workflow.
- После получения `.exe` откройте его в Windows и проверьте на своих рабочих EDI/Excel-файлах. Перед отправкой EDI принимающему терминалу обязательно сверяйте требования этого терминала.

## Работа со скелетом судна в v1.07

1. Заполните реальные позиции на листе `POSITIONS` шаблона `Vessel_Skeleton_Template.xlsx` (Bay, Row, Tier, Area, Position status). Удалите демонстрационные строки или замените их данными из Manual.
2. В приложении нажмите `Загрузить скелет судна…` и выберите этот Excel-файл.
3. На вкладке `Графика` нажмите `Показать скелет / контейнеры`, чтобы увидеть пустую структуру. Можно сохранить её в JPG.
4. Импортируйте EDI обычным способом. Чтобы видеть контейнеры поверх скелета, выключите режим пустого скелета той же кнопкой. Контейнерные данные сохраняются при переключении.

Пустой шаблон без фактических координат не содержит достаточной геометрии, чтобы приложение могло достоверно нарисовать конкретное судно. Заполняйте позиции по Manual; не используйте DEMO-строки для реального плана.


## Версия 1.08 — проверка, поиск, PDF и печать

- Перед экспортом EDI и Excel показываются найденные ошибки и предупреждения. В окне проверки можно перейти к контейнеру и увидеть его позицию на схеме.
- Поиск по плану поддерживает все поля контейнера, включая вес `GROSS_KG`, и выделяет совпадения на графике.
- Вкладка плана предлагает экспорт в JPG или PDF. «Печать плана» создаёт PDF и пытается отправить его в приложение печати Windows. Если автоматическая печать не поддерживается установленным PDF-просмотрщиком, откройте созданный PDF и используйте Ctrl+P.
- Скелет судна по-прежнему необязателен: без него графика работает в обычном режиме.

См. `CHANGELOG_V1.08.md`.


## Версия 1.09 — библиотека судов и выбор скелета

- Добавлена отдельная вкладка **«Судна»** с перечнем загруженных Excel-скелетов: название судна, IMO, число распознанных позиций, имя файла и путь хранения.
- При добавлении скелет копируется в `Документы\CV Container Ship\VesselSkeletons`, а запись сохраняется в `config.json`. Перемещение исходного файла больше не ломает библиотеку.
- На вкладке «План судна» кнопка **«Показать скелет / контейнеры»** открывает перечень судов и позволяет выбрать пустой скелет или отображение контейнеров поверх него.
- Старый выбранный скелет переносится в новый перечень автоматически, если файл всё ещё доступен. Удаление из перечня запрашивает подтверждение.

Для проверки загрузите файл скелета на вкладке «Судна», затем откройте «План судна» → «Показать скелет / контейнеры» и выберите режим отображения.


## Сборка EXE для версии 1.09

Используйте файлы из архива `CV_Container_Ship_v1.09_GitHub_Build.zip`. Загрузите их в корень GitHub-репозитория и замените `.github/workflows/build-windows.yml` содержимым `WORKFLOW_TO_COPY.yml`. В Actions запустите **Build CV Container Ship v1.09 for Windows** и скачайте артефакт `CV_Container_Ship_v1.09_Windows_EXE`. Локальная сборка в Windows выполняется через `build_windows.bat`. Архив содержит исходники и сценарий сборки, но не готовый EXE.


## Версия 1.11 — ускорение работы

- Повторное чтение координат скелета из Excel заменено кешированием: при перерисовке плана используются уже загруженные данные.
- Разбор листа `POSITIONS` выполняется пакетным чтением строк.
- Для старых графических скелетов кешируются извлечённые Bay / Row / Tier.
- Метаданные судна сохраняются в реестре; при неизменённом файле приложение не открывает Excel повторно только ради названия, IMO и количества позиций. Замена файла определяется по размеру и времени изменения.
